# 架构

使用原生微信小程序，避免浏览器 DOM、Node 专有模块、外部 UI 包进入运行时。项目根的 Node 脚本仅用于检查与测试。没有构建步骤，核心代码直接与小程序共用。

数据流：手动录牌 → domain 校验/拆解 → pattern 输出 → 已确认的规则策略 → 页面结果。每张牌以 m1..m9 / p1..p9 / s1..s9 表示；concealed 包含胡牌张；melds 为 pong/kong + tile；missingSuit 必填。杠占一个面子，实体数量校验计四张。

算法穷举将牌，递归拆解顺子/刻子，保留所有可行拆解，避免只取第一种拆解而漏掉对对胡。七对单独判断；四张相同牌可构成两对。校验实体牌数量、同牌上限、定缺及副露种类。

本阶段不是整局规则模拟器：不判断过手胡、换三张、点炮资格、最后四张强制胡等历史依赖条件；已支持用户声明的自摸、杠上花、杠上炮、抢杠、海底、天地胡、报叫，以及从牌面/副露判断幺九、将对、金钩钓。参考番表与场规可编辑，计算单份胡牌分值，不计算查叫、花猪、退税、独立杠结算和多家结算。规则来源与取舍见 rules.md，不宣称完整复刻某一赛事。

照片方向：只有用户主动发起才调用隐私授权和媒体 API。使用官方隐私弹窗，拒绝/取消后保留手动路径。最低能力不足时提示更新，不能绕过授权。当前没有拍照按钮，photoEnabled 与 recognitionReady 均为 false。真实识牌后须先人工纠牌再计算；低置信度不能直接出番数。

后端接入时采用受控微信云服务或已配置的 HTTPS 域名；密钥在服务端，上传前披露用途、留存与第三方处理，设置限流及文件大小校验。当前版本不发送网络请求、不保存手牌或照片，不做统计采集。

地区导航：首页 → 地区 → 玩法；成都继续进入录牌算番。domain/regions.js集中配置入口，assets/regions为本地线稿。位置适配层先隐私授权后读取一次位置，仅做本地附近城市匹配。
